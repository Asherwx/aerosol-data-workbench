# 大气气溶胶数据工作台设计规格

日期：2026-08-07  
状态：待用户书面审阅  
目标部署：公开 GitHub Pages

## 1. 项目目标

建设一个面向安徽理工大学课题组的大气气溶胶数据初步整理网页。任何人都可以打开网页，但用户上传的数据只在本地浏览器中处理，不上传服务器。

第一版解决五项工作：

1. 按日期生成全国国控站逐日数据下载链接。
2. 导入多个 `china_sites_*.csv` 并验证文件、日期和格式。
3. 提取目标站点的六项常规污染物，默认站点为山南新区 `3329A`。
4. 上传水溶性离子 Excel，按北京时间逐时合并并完成基础数据质控。
5. 导出整理表、质控报告和处理日志。

第一版不实现 SOR、NOR、RH 分层、昼夜分层、滞后相关和机制图。这些能力保留为后续扩展模块。

## 2. 成功标准

- GitHub Pages 公开地址可以在无需登录的情况下访问。
- 用户可分别运行每一步，也可点击“一键完成全部”。
- 61 个 2024 年 11—12 月逐日 CSV 可以在桌面浏览器中顺序处理，不因一次性加载全部全国站点数据而崩溃。
- 网页对 `3329A` 的提取结果与已验证 Python 结果一致。
- 处理结果覆盖 2024-11-01 00:00 至 2024-12-31 23:00 的 1464 小时时间轴。
- 缺测、重复、负值、时间断点和六项同时为 0 等问题不会被静默删除。
- 所有异常均保留原值并写入质控标记和处理日志。

## 3. 使用者与权限

- 主要使用者：课题组成员。
- 访问方式：公开网页。
- 登录：第一版不设置账号或口令。
- 数据隐私：文件只在用户浏览器内存中处理；不发送到服务器，不写入 GitHub，不进行遥测上传。
- 设备：电脑端为完整功能设备；手机端可浏览页面与说明，但大文件处理显示“建议使用电脑”。

## 4. 信息架构

采用单页结构：

1. 首页主视觉。
2. 数据工作台。
3. 流程说明与数据口径。
4. 课题组与项目说明。

首页“开始处理数据”滚动并聚焦数据工作台，不新增独立登录页或营销页面。

## 5. 视觉设计

### 5.1 已确认方向

使用真实山脉、动态体积雾和气溶胶悬浮粒子，表现大气过程的空间深度。不得使用平面矢量山形作为主视觉。

已确认的视觉概念：

- 动态概念页：`<LOCAL_DESIGN_SESSION>/content/realistic-dynamic-v2.html`
- 主视觉背景：`<LOCAL_DESIGN_SESSION>/content/aerosol-hero-real.png`

实施时将最终背景资产复制到项目 `public/assets/`，不依赖临时概念目录。

### 5.2 动效

- 三层不同速度的雾层水平漂移。
- 背景以极慢速度推进，形成镜头呼吸。
- 低密度气溶胶粒子缓慢上浮。
- 桌面端鼠标产生轻微视差；触摸设备不启用鼠标视差。
- 遵循 `prefers-reduced-motion`，减少动态时停止持续动画并保留静态主视觉。

### 5.3 视觉系统

- 主色：炭蓝、石板蓝、低饱和青色、珍珠雾白。
- 避免：高饱和霓虹、廉价发光描边、大面积纯黑、通用平面卡片网格。
- 页面主标题：中文，强调“让不可见的大气过程可分析”。
- 数据工作台采用“科研观测舱”而非营销卡片：左侧流程、中部操作、右侧实时检查。
- 已完成状态为柔和青绿；提示为琥珀色；错误信息不使用大面积刺眼红色。

## 6. 工作流与交互

### 6.1 第一步：生成下载链接

输入：开始日期、结束日期。  
输出：`china_sites_YYYYMMDD.csv` 链接清单。

- 检查日期格式和先后顺序。
- 提供逐个下载按钮和复制全部链接。
- 只有在目标站点支持跨域请求且浏览器允许批量下载时才显示“自动批量下载”。
- 若浏览器阻止多文件下载，保留链接清单并给出手动下载说明，不将其视为流程失败。

### 6.2 第二步：导入国控站数据

输入：多个 `china_sites_*.csv`。  
检查：

- 文件是否为空或为错误网页。
- 表头是否包含 `date`、`hour`、`type` 和目标站点列。
- 日期是否与文件名一致。
- 是否存在重复文件、重复日期和缺失日期。
- UTF-8 编码是否可解析。

解析采用逐文件策略。每个文件只保留六项瞬时污染物行以及目标站点列，处理完成后释放全国站点原始矩阵。

### 6.3 第三步：提取站点

默认站点：`3329A`。  
污染物：`SO2`、`NO2`、`O3`、`CO`、`PM10`、`PM2.5`。

输出列：

- `时间`
- `SO2_μg_m3`
- `NO2_μg_m3`
- `O3_μg_m3`
- `CO_mg_m3`
- `PM10_μg_m3`
- `PM2.5_μg_m3`
- `缺测项目`
- `数据状态`

时间轴按最早与最晚日期补齐为连续北京时间整点。缺测保持空值，不使用 0 填充。

### 6.4 第四步：合并与质控

输入：提取后的站点数据、水溶性离子 Excel。  
离子列至少识别：时间、NO3、SO4、NH4。其他离子存在时一并保留。

检查：

- 时间列能否解析为北京时间整点。
- 重复时间与时间断点。
- 核心变量缺测。
- 数值字段中的文本和非法值。
- 负浓度。
- 六项污染物同时为 0。
- 可配置的异常高值提示。
- 单位名称是否符合预期。

质控只增加 `QC_flag`、`QC_keep` 和说明列，不覆盖原始观测值。

### 6.5 第五步：导出

允许分别下载：

1. `{站点}_逐时六常规.csv`
2. `离子_国控站_逐时合并.xlsx`
3. `数据质控报告.xlsx`
4. `处理日志.json`

处理日志记录输入文件名、参数、时间范围、原始行数、有效行数、异常类型统计、运行时间和网页版本号。

### 6.6 一键完成

一键流程依次调用五个独立步骤，不复制第二套逻辑。

- 缺少必要输入时停在对应步骤并说明需要的文件。
- 已完成结果保留，可从失败步骤继续。
- 用户更改站点、日期或文件后，相关下游步骤标记为需要重新运行。

## 7. 技术架构

- React 18+
- TypeScript
- Vite
- Papa Parse：CSV 解析
- SheetJS：Excel 读取与导出
- JSZip：结果打包
- Web Worker：逐文件解析与质控计算
- Vitest：单元测试
- Playwright：关键流程端到端测试
- GitHub Actions：构建和 GitHub Pages 部署

状态分为：

- 页面与步骤状态：React 状态。
- 大型原始文件：只在当前处理周期的浏览器内存中存在。
- 用户偏好：站点编号、减少动态效果等可写入 localStorage。
- 研究数据与结果：不写入 localStorage 或 IndexedDB，除非后续版本得到明确批准。

现有 Python 脚本放入 `reference-python/`，用于离线备用和结果对照，不由 GitHub Pages 执行。

## 8. 模块边界

- `download-links`：日期与下载地址生成，不读取研究文件。
- `station-csv-parser`：验证和提取单个逐日 CSV。
- `station-series`：合并逐日提取结果、补齐时间轴。
- `ion-workbook-parser`：识别并标准化离子工作簿。
- `hourly-merge`：按北京时间逐时连接两类数据。
- `quality-control`：产生标记和统计，不改变观测值。
- `exports`：生成 CSV、XLSX、JSON 与 ZIP。
- `pipeline`：编排独立模块并维护步骤状态。
- `ui`：只展示状态和触发操作，不包含数据计算规则。

## 9. 错误处理

错误分为：

- 阻断错误：必要列缺失、站点不存在、文件不可解析。停止当前步骤。
- 数据警告：缺测、重复、负值、异常 0 值。保留数据并允许继续。
- 浏览器限制：批量下载被阻止、内存不足。给出恢复方法和已完成状态。

所有错误包含：问题、影响、建议操作和涉及的文件名或时间点。不得只显示“处理失败”。

## 10. 测试与验收数据

使用已有 2024 年 11—12 月数据验证：

- 61 个 `china_sites_*.csv`。
- 目标站点 `3329A`。
- 1464 小时完整时间轴。
- 与现有 Python 输出逐项比较六项污染物。
- 验证 2024-11-15 18:00 六项同时为 0 的异常标记。
- 验证缺失日期、重复文件、错误站点、错误编码和空文件。
- 验证离子 Excel 时间列、主要离子列和逐时合并。
- 验证 Chrome/Edge 桌面端、移动端布局和减少动态效果模式。
- 在 GitHub Pages 正式地址完成一次下载链接生成、文件导入、站点提取、合并、质控和导出。

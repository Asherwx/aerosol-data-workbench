# 双入口连续数据处理工作台设计

日期：2026-08-09  
状态：待用户最终审阅

## 1. 目标

将现有“生成下载链接后再手动导入”的流程改为两条平行数据入口，并保证入口完成后，数据在后续步骤间直接传递：

1. 在线获取数据：生成全国原始数据链接，或下载并提取指定站点数据；
2. 直接导入数据：导入本地 CSV 后自动识别并解析；
3. 两条主路径汇合为同一种已解析站点记录；
4. 后续步骤直接使用上一步结果，不要求重新导入、另存格式或手动转换。

本次同时调整首屏视觉、课题组品牌、步骤导航和第三步质控结构。

## 2. 信息架构

页面保留一个首屏和一个单步骤工作区。首屏展示四张可点击的阶段卡：

1. STEP 01：获取或导入数据；
2. STEP 02：构建逐时序列；
3. STEP 03：数据质控；
4. STEP 04：导出结果。

步骤卡是真实按钮或锚点。点击后滚动至工作区并激活对应阶段。工作区一次只显示当前阶段的输入、操作和结果，其他阶段内容不同时展开。

切换阶段不会清除已经完成的数据。若用户进入尚未满足前置条件的阶段，页面显示缺少的内容，并提供返回上一阶段的按钮。

## 3. STEP 01：获取或导入数据

第一步打开后提供两个平行入口。

### 3.1 在线获取数据

在线获取区包含两个独立功能。

#### 3.1.1 生成全国原始数据链接

- 只输入起始日期和结束日期；
- 不显示或要求站点编号；
- 生成 `china_sites_YYYYMMDD.csv` 公开源文件链接；
- 链接为辅助功能，本身不视为完成第一步，也不自动进入处理链。

#### 3.1.2 下载指定站点数据

- 输入起始日期、结束日期和站点编号；
- 日期跨度最多 366 天；
- 浏览器通过 Cloudflare Worker 逐日获取公开源数据；
- Worker 每次只处理一个日期和一个站点，避免单次请求包含大量上游子请求；
- 浏览器使用有界并发请求多个日期，显示逐日进度并支持取消；
- 浏览器合并每天返回的站点记录，生成一个逐时 CSV，例如 `3329A_20241101_20241231.csv`；
- 成功后同时执行两件事：将 CSV 下载给用户，并将相同内容直接转换为页面内的已解析站点记录；
- 用户不需要再进入本地导入入口上传刚下载的文件。

Cloudflare Worker 接口为单日查询：

```text
GET /v1/station-day?date=YYYY-MM-DD&station=3329A
```

返回结构包括该站点当天的逐时记录、源文件状态和有界警告信息。Worker 仅允许访问预设公开数据源，并限制日期格式、站点格式、上游文件大小、超时和响应大小。

### 3.2 直接导入数据

本地导入支持：

- 多个全国逐日原始 CSV；
- 单个已经提取的站点逐时 CSV。

选择文件后立即执行格式识别和解析，不再保留“提取站点数据”的二次按钮。解析成功后直接产生与在线指定站点下载相同的数据结构。

原始逐日文件按 `china_sites_YYYYMMDD.csv` 规则验证日期；站点逐时文件验证时间列、站点编号和六项污染物列。无法识别时显示具体缺失列或格式问题，不静默跳过。

## 4. 连续处理链

### 4.1 STEP 02：构建逐时序列

- 直接读取第一步已经解析的站点记录；
- 用户点击“构建逐时序列”后执行；
- 不要求重新导入或转换；
- 输出连续时间轴、起止时间、缺失小时数、重复冲突警告和数据预览；
- 完成后启用“进入下一步”。

### 4.2 STEP 03：数据质控

第三步提供两个可切换的独立模式。用户可任选一个，也可先后运行两个；两套结果分别保存、互不覆盖。

#### 模式 A：站点数据质控

- 直接使用第二步的连续逐时序列；
- 检查缺失小时、缺失值、非有限值、负值和六项污染物同时为零；
- 保留原始数值，不自动删除、填补或修改；
- 输出带标记完整数据、正常数据、异常数据和质控统计。

#### 模式 B：用户数据合并质控

- 支持用户数据 CSV 和 XLSX；
- 自动识别常见时间列、水溶性离子列和单位；
- 无法可靠识别时显示列映射界面，由用户确认时间列、变量列和单位；
- 与第二步站点序列按精确小时合并；
- 标记站点缺失、用户数据缺失、未匹配时间、非有限值、已知非负变量的负值和单位问题；
- 对已知 NO3⁻、SO4²⁻、NH4⁺ 等变量使用现有明确规则；其他用户列默认只做缺失与非有限值审计，不擅自假定负值无效；
- 模式内部自动包含模式 A 的站点质控规则；
- 输出合并完整表、正常表、异常表、未匹配时间表和处理日志。

### 4.3 STEP 04：导出结果

- 直接使用第三步已运行模式的结果；
- 模式 A 输出站点质控 CSV、统计表、日志和 ZIP；
- 模式 B 输出合并完整表、正常表、异常表、未匹配表、工作簿、日志和 ZIP；
- 两种模式均运行时显示两套独立结果包；
- 每个文件可单独下载，也可下载完整结果包。

### 4.4 一键完成后续处理

“一键完成后续处理”从当前已完成位置继续：

- 不重复下载、解析或上传；
- 不清除已经完成的结果；
- 缺少必须的用户输入时停在对应步骤并说明原因；
- 用户补充输入后从停留位置继续。

## 5. 状态、失败和恢复

- 在线日期范围最多 366 天；
- 在线指定站点下载显示已完成天数、总天数、失败天数和取消按钮；
- 单日文件缺失不终止整个任务，而是记录警告，并在第二步连续序列中形成缺失小时；
- 站点不存在、日期无效或所有日期均失败时停止并显示原因；
- 在线任务取消后终止未完成请求，迟到响应不得修改界面状态；
- 本地 CSV/XLSX 使用现有安全预检、大小限制和后台解析；
- 任一步失败时保留之前成功的输入和结果；
- 修改上游输入时只使相关下游结果失效，不清除无关结果；
- 警告有总数、展示上限和省略数量，避免页面或日志无界增长。

## 6. Cloudflare Worker 边界

Worker 只承担公开源文件的单日获取和指定站点提取，不保存用户上传文件或研究数据。

安全边界：

- 上游域名固定白名单，不接受任意 URL；
- 严格验证日期和站点编号；
- 设置连接超时、响应大小和解析行数上限；
- CORS 仅允许正式 Pages 地址和明确的本地开发地址；
- 不记录原始响应、站点记录或查询参数中的敏感内容；
- 错误响应不返回内部堆栈或本地路径；
- 部署配置不将密钥提交到 Git。

## 7. 视觉设计

### 7.1 品牌

- 页眉课题组名称统一为“江峰课题组”；
- 删除“安徽理工大学课题组”；
- 删除“本地处理 · 数据不离开浏览器”字样；
- README 和测试同步更新，不再作不准确的全局“仅浏览器处理”承诺。

### 7.2 静态背景

- 使用确认过的原创生成山地云雾摄影方向；
- 图片为静态，不使用动态雾、粒子、镜头呼吸或视差；
- 桌面端使用高分辨率 WebP 和 PNG 回退；
- 手机端提供独立裁切或响应式尺寸；
- 左侧保留标题留白，右侧突出山脊和云雾层次；
- 正式资产使用版本化文件名，避免覆盖旧图后缓存错配。

### 7.3 标题排版

采用方案 C：英文小号引导线位于中文主标题上方。

```text
— MAKING INVISIBLE ATMOSPHERIC PROCESSES ANALYZABLE

让不可见的
大气过程可分析
```

英文使用小号大字距，中文保持主要视觉层级。标题、正文和主按钮之间增加留白，维持桌面和手机端清晰层级。

## 8. 可访问性与响应式

- 步骤卡使用语义化按钮或链接，不使用伪按钮；
- 当前步骤使用 `aria-current="step"`；
- 两种数据入口和第三步两种模式使用可键盘操作的标签页或单选卡；
- 忙碌状态禁用冲突操作，保留可用的取消按钮；
- 进度和错误使用实时区域与明确标签；
- 桌面保留导航、工作框和检查摘要层级；
- 手机端步骤导航可横向滚动，当前工作框纵向排列，无页面级横向溢出；
- 由于背景不再动画，减少动态模式仍保留并覆盖其他必要过渡效果。

## 9. 测试与验收

### 9.1 单元与契约测试

- Worker 日期、站点、白名单、大小、超时和错误边界；
- 在线逐日结果聚合、部分失败、取消和迟到响应；
- 原始逐日 CSV 与已提取站点 CSV 自动识别；
- 导入后自动解析，不需要二次按钮；
- 上一步结果直接成为下一步输入；
- 第三步两种模式独立运行、独立失效和独立导出；
- CSV/XLSX 时间与列自动识别及手动映射；
- 原始零值保留和质控标记；
- 静态背景不包含动画声明；
- 品牌和中英文标题文案准确。

### 9.2 浏览器端到端测试

- 点击四张步骤卡均打开对应单步骤工作框；
- 生成全国原始链接不要求站点；
- 在线指定站点下载后直接进入第二步，无重新上传；
- 本地原始 CSV 和站点 CSV 导入后自动解析；
- 模式 A 站点质控完整流程；
- 模式 B CSV 合并质控完整流程；
- 模式 B XLSX 合并质控完整流程；
- 两种模式都运行后显示两套结果包；
- 一键处理从当前进度继续；
- 桌面和手机端无控制台错误、页面错误或横向溢出。

### 9.3 发布验收

- 前端 GitHub Pages 与 Worker 分别部署；
- 正式前端只调用正式 Worker 地址；
- Worker CORS 允许正式 Pages 地址；
- 当前文件、提交元数据和完整可达历史通过隐私审计；
- 公开仓库不包含研究原始数据、Worker 密钥或本机路径；
- 线上完成在线下载、本地导入、两种质控和结果下载冒烟测试。

## 10. 明确不做

- 不直接使用国家地理或其他版权不明的图片；
- 不在 GitHub Pages 中运行 Python；
- 不让 Worker 接收任意第三方下载地址；
- 不对未知用户变量擅自应用科学含义或负值规则；
- 不在同一屏同时展开四个步骤的全部内容；
- 不要求用户下载中间文件后重新导入。

## 11. 验收标准

设计视为完成需同时满足：

1. 两条数据入口平行且清晰；
2. 指定站点在线下载产生真实 CSV，并直接进入处理链；
3. 本地导入后自动解析；
4. 后续步骤不重复导入或转换；
5. 第三步两种模式可任选并独立输出；
6. 所有步骤卡可点击，页面一次只显示一个步骤；
7. 静态背景、江峰课题组和方案 C 标题排版落实；
8. 前端、Worker、隐私、安全、可访问性和线上流程测试全部通过。
